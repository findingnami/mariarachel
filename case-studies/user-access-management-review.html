Case Study

User Access Management Review

Reviewing user roles, permissions, and access removal across internal commission, project management, and CRM applications, and building safeguards to keep access appropriate.

Focus area
User access and permissions
Context
Three internal business applications at a technology advisory firm
Tools
Supabase · Role-based access · Two-factor authentication · Activity logs
Role
Operations Intelligence Manager

Overview

At a technology advisory firm, I reviewed who had access to what across three internal business applications: commission tracking, project management, and CRM. The aim was to make sure access matched each person's role and was removed when it was no longer needed.

Risk & objective

Internal applications hold contract, commission, and client information. Excess permissions, or accounts that stay active after a role change or departure, create risk of unauthorized viewing or changes. The objective was to keep access limited to what each role needs and to catch access that should be removed.

What I did

  • Reviewed user roles and permissions across the commission, project management, and CRM applications.
  • Checked that access was removed when it was no longer needed.
  • Applied role-based access so that each role sees and changes only what it needs.
  • Added data restrictions to limit what each role can see or change.
  • Enabled two-factor authentication for application sign-in.
  • Used activity logs to keep a record of user actions.

Controls in place

  • Role-based access
  • Data restrictions
  • Two-factor authentication
  • Activity logs
  • Access removal review

Result

Access across the three applications is governed by defined roles, with safeguards built into the applications instead of relying on manual checks alone.

What this shows

I can review access against a defined standard, build the control into the system, and keep evidence of it. These are the same steps used in user access reviews and IT general controls testing.

Skills demonstrated

  • Data Restrictions
  • Two-Factor Authentication
